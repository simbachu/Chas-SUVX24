intmath.py API overview

isprime(n)

  • params: n int
  • returns: bool (prime test)
  • boundaries: n<=1 → False, n==2 → True, even >2 → False
  • deps: none (internal logic only)

nextprime(n)

  • params: n int
  • returns: next prime strictly greater than n (special: n<=1 → 2, n==2 → 3)
  • boundaries: recurses; large n may hit recursion limits
  • deps: isprime

primefactors(n)

  • params: n int
  • returns: list[int] of prime factors (with multiplicity); n<=1 → []
  • boundaries: trial division; may be slow for large primes
  • deps: nextprime

power(c, n)

  • params: c number, n any
  • returns: c^n; if n is not int uses floating math.pow
  • boundaries: supports negative and zero integer exponents; recursion depth logarithmic for int n
  • deps: math.pow

factorial(n)

  • params: n int
  • returns: n! int; n<0 → None
  • boundaries: memoized (_fact_mem with 0:1); recursion depth O(n)
  • deps: _fact_mem dict

fibbonacci(n)

  • params: n int (1-indexed: _fib_mem={1:0,2:1})
  • returns: n-th Fibonacci; n<0 → None
  • boundaries: n==0 causes invalid recursion (adds None); recursion heavy despite memo write; inconsistent return uses recomputation
  • deps: _fib_mem dict

combination(n, k)

  • params: n int, k int
  • returns: binomial coefficient via recursion; base: n==k or k==0 → 1; else → various recursive cases
  • boundaries: behavior for k>n, k<0, n<0 not well-defined; may be inefficient/deep recursion
  • deps: self-recursive only
  • BUG: invalid domains (n<0, k<0, k>n) are not guarded; function may return an int instead of None as implied.

Module-level

  • imports: math
  • state: _fact_mem, _fib_mem

Large n expectations (default Python recursionlimit ≈ 1000)

  • factorial(n): depth ≈ n → risk for n ≳ 950–990 (RecursionError)
  • fibbonacci(n): depth ≈ n (top-down recursion) → risk for n ≳ 950–990
  • combination(n,k): depth can approach max(n, k, n−k) depending on branch → risk when any dimension ≳ 950–990
  • nextprime(n): depth ≈ prime gap after n; typically <100; safe for usual inputs
  • power(c,n): depth ≈ O(log2(|n|)) for int n → safe up to very large |n|
  • primefactors(n): iterative; safe, but time grows with size of n

Notes: Use sys.getrecursionlimit() to inspect and sys.setrecursionlimit(v) to raise if truly needed; prefer iterative/memoized forms for robustness.
